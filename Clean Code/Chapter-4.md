                                                                Comments











Comments are a necessary evil, if our programming languages were expressive enough,we would not need comments very much
We should use comments when we fail to compensate for our failure to express ourself in code
Comments should be in a high state of repair,relevance and accuracy
Comments do not make up for bad code
ONly truly good comment is the comment you found a way not to write

It is sometimes useful to provide basic information with a comment. For example, con-
sider this comment that explains the return value of an abstract method:
// Returns an instance of the Responder being tested.
protected abstract Responder responderInstance();
A comment like this can sometimes be useful, but it is better to use the name of the func-
tion to convey the information where possible.

You can explain the intent behind a function in a comment
You can make a clarification comment say when you are using a standard library and you cant really mess with the code
You can make comments to warn other programmers about some certain consqeuences
You can make amplification comments to highlight the importance of something

If you spend your time writing a comment, then spend the time necessary to make sure it is the best comment you can write

You comments cannot take longer to read than the code
Dont make noise comments: Restating the obvious things
Just dont write commented out code,others w ho see it may not have the courage to delete it
If you writing a comment, make sure it is explaining the code near it,
Dont put al historical infoemation in comments
